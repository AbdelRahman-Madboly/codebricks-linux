# Open Source Software Development Methods

Study notes for the "methods" side of open source: what OSS *is*, how people *work together*
on it, and what makes a project *survive*. This is the conceptual / process material — not Linux
commands. For the hands-on Linux skills see [`../../../src/`](../../../src/); for the practical
"how do I actually do this" tables see [`../../reference/`](../../reference/).

> These are my own notes in my own words. Read them to study; they're meant to be searchable and
> revisited before an interview.

---

## Why this matters

Almost every modern tech company either builds on, contributes to, or releases open source. A
support or engineering role means you will read other people's public code, file issues, send
patches, and reason about licences. Knowing *how the open source world works socially and legally*
is as important as knowing the tools.

## How each doc is shaped

Every section follows the same rhythm so it's fast to study:

1. **Concept** — the idea in plain language.
2. **Why it works this way** — the reasoning, not just the fact.
3. **In practice** — how it shows up when you actually use or contribute to OSS.
4. **Check yourself** — questions at the end you should be able to answer out loud.
